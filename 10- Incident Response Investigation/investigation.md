# Investigation Report — Lab 10

## Incident Summary

A Splunk alert was triggered after multiple failed authentication attempts were detected for a Windows user account. An investigation was conducted to determine whether the activity represented a legitimate security incident or expected system behavior. Windows Security Event Logs were analyzed using Splunk Search Processing Language (SPL) to collect evidence, reconstruct the sequence of events, and determine the root cause.

---

## Investigation Objective

The objectives of this investigation were to:

- Investigate the authentication alert generated by Splunk.
- Identify the affected user account.
- Build a timeline of authentication events.
- Determine whether unauthorized access occurred.
- Identify the root cause of the alert.
- Assess the severity of the incident.
- Recommend appropriate security actions.

## SPL Queries Executed

### Review Failed Authentication Attempts

```spl
source="WinEventLog:Security" EventCode=4625
```

---

### Build Authentication Timeline

```spl
source="WinEventLog:Security" (EventCode=4624 OR EventCode=4625)
| table _time Account_Name EventCode host
| sort _time
```

---

### Review User Activity

```spl
source="WinEventLog:Security"
| top Account_Name
```

---

### Review Host Activity

```spl
index=* | top host
```

## Investigation Findings

The investigation identified the following:

- Multiple failed authentication attempts were recorded in the Windows Security Event Log.
- Splunk successfully collected and indexed the authentication events.
- Authentication events were reconstructed into a chronological timeline.
- The affected user account and host were successfully identified.
- No evidence of successful unauthorized access was observed.
- No indicators of compromise (IOCs) were identified during the investigation.

---

## Root Cause Analysis

The failed authentication attempts were intentionally generated during lab testing by entering an incorrect Windows password multiple times.

This controlled activity produced Windows Event ID **4625**, which triggered the detection rule created in Lab 09.

The alert confirmed that the detection rule functioned correctly and that Splunk successfully collected and indexed the relevant authentication events.

No malicious activity or unauthorized access occurred during the investigation.

---

## Severity Assessment

### Severity Level

**Informational**

### Justification

Although repeated failed login attempts were detected, the activity occurred during controlled testing for validation purposes. The authentication failures were expected, and there was no evidence of account compromise, privilege escalation, or unauthorized access.

---

## Recommendations

Based on this investigation, the following recommendations are made:

- Continue monitoring failed authentication events.
- Configure automated alerts for excessive failed login attempts.
- Enable account lockout policies to reduce the risk of brute-force attacks.
- Regularly validate SIEM detection rules through controlled testing.
- Retain Windows Security Event Logs to support future investigations.
- Review authentication logs periodically for abnormal user activity.

---

## Lessons Learned

This investigation reinforced several important concepts:

- SIEM alerts should always be validated before assuming malicious activity.
- Authentication events provide valuable evidence during investigations.
- Timeline analysis improves understanding of security events.
- Controlled testing is an effective method for validating detection rules.
- Proper documentation is essential for consistent incident response.

---

## Conclusion

This investigation successfully demonstrated the complete incident response workflow for an authentication-related alert. Evidence was collected from Windows Security Event Logs, authentication events were analyzed, a timeline was constructed, and the root cause was identified.

The investigation confirmed that the failed login attempts were intentionally generated as part of a controlled lab exercise to validate a Splunk detection rule. No unauthorized access or malicious activity was identified. The incident was therefore classified as **Informational**, and the investigation was closed after confirming that the detection operated as expected.
